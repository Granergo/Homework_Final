# Link Shortener

Консольное Java-приложение для создания и управления короткими ссылками. Приложение генерирует уникальные короткие коды, учитывает количество переходов, ограничивает срок действия ссылок и позволяет пользователям управлять только собственными ссылками.

## Возможности

- Создание пользователей с уникальными UUID без регистрации пароля.
- Создание коротких ссылок для URL с протоколом `http` или `https`.
- Генерация уникального короткого кода для каждой ссылки.
- Установка максимального количества переходов.
- Учёт успешных переходов и блокировка ссылки после исчерпания лимита.
- Ограничение срока действия ссылки (TTL).
- Автоматическая периодическая очистка просроченных ссылок во время работы приложения.
- Просмотр собственных ссылок, изменение их лимита и удаление.
- Проверка владельца перед изменением или удалением ссылки.
- Уведомления о событиях истечения TTL, исчерпания лимита и ошибках планировщика.
- Реализации файловых репозиториев для хранения пользователей и ссылок в JSON с восстановлением состояния.
- Конфигурация TTL, максимального лимита, длины короткого кода, интервала очистки и путей к хранилищам.

## Конфигурация

Файл конфигурации `config.properties` должен находиться в корне проекта. Параметры читаются классом `AppConfig`.

Пример конфигурации (значения можно менять под свои задачи):

```properties
# Время жизни короткой ссылки в секундах (86400 = 24 часа)
link.ttl.seconds=86400

# Максимально допустимый лимит переходов для одной ссылки
link.max-clicks=1000

# Длина генерируемого короткого кода
link.code.length=10

# Интервал автоматической очистки в секундах
link.cleanup.interval.seconds=60

# Пути к JSON-файлам
storage.users-file=data/users.json
storage.links-file=data/links.json
```

| Параметр | Назначение | Ограничения / пример |
|---|---|---|
| `link.ttl.seconds` | Срок жизни новой ссылки | Положительное число секунд; `86400` = 24 часа |
| `link.max-clicks` | Максимальный разрешённый лимит переходов | Положительное целое число |
| `link.code.length` | Длина короткого кода | От 4 до 32 символов |
| `link.cleanup.interval.seconds` | Интервал фоновой очистки | Положительное число секунд |
| `storage.users-file` | Путь к файлу пользователей | Например, `data/users.json` |
| `storage.links-file` | Путь к файлу ссылок | Например, `data/links.json` |

Относительные пути к JSON-файлам разрешаются относительно директории, в которой расположен `config.properties`. Абсолютные пути также поддерживаются. Пути пользователей и ссылок должны быть разными. Если в `config.properties` установлено `link.ttl.seconds=10`, новая ссылка действует только 10 секунд; для 24 часов укажите `86400`.

Значения конфигурации проверяются при загрузке. Отсутствующие обязательные параметры, некорректные числа и недопустимые диапазоны приводят к ошибке конфигурации.

## Работа с приложением

После запуска отображается главное меню:

```text
1. Выбор пользователя
2. Создать короткую ссылку
3. Перейти по короткой ссылке
4. Управление моими ссылками
5. Помощь
0. Выход
```

### 1. Выбор пользователя

Можно создать нового пользователя или выбрать ранее сохранённого. Пользователь идентифицируется UUID. Если пользователь не выбран, при создании ссылки приложение автоматически создаёт нового пользователя.

### 2. Создание короткой ссылки

Введите исходный URL и положительный целочисленный лимит переходов. Поддерживаются URL с `http` и `https` и корректным именем хоста.

Пример URL:

```text
https://example.com/articles/42
```

После успешного создания приложение показывает короткий код. Ввод `0` на шагах ввода URL или лимита отменяет операцию.

### 3. Переход по короткой ссылке

Введите короткий код. Если ссылка существует, не просрочена и лимит не исчерпан, приложение вызывает браузер компьютера и учитывает переход.

Возможные результаты:

- `OPENED` — браузер вызван, переход учтён.
- `NOT_FOUND` — короткий код не найден.
- `EXPIRED` — срок действия ссылки истёк.
- `LIMIT_REACHED` — лимит переходов исчерпан.

Если браузер не удалось открыть, приложение отменяет резервирование перехода. Ввод `0` отменяет операцию.

### 4. Управление моими ссылками

Для доступа необходимо выбрать пользователя. Доступны действия:

1. **Просмотреть мои ссылки** — показывает короткий код, исходный URL, счётчик и лимит переходов, статус, даты создания и истечения.
2. **Изменить лимит переходов** — новый лимит должен быть положительным, не превышать глобальный максимум и не быть меньше уже совершённого числа переходов.
3. **Удалить ссылку** — удаляет выбранную ссылку после подтверждения вводом `ДА`.

Проверка владельца выполняется в сервисном слое. Нельзя изменить или удалить ссылку другого пользователя.

### 5. Помощь

Выводит справку с назначением команд, правилами URL, лимитами, TTL и пояснением статусов перехода.

### 0. Выход

Завершает работу приложения. При выходе фоновый планировщик должен корректно завершить работу.

## Хранение данных

Файловые репозитории реализуют интерфейсы `UserRepository` и `LinkRepository`. Благодаря этому сервисы могут работать с абстракциями и не зависят от конкретного способа хранения. Чтобы постоянное хранение использовалось при обычном запуске приложения, `Main` должен создавать `FileUserRepository` и `FileLinkRepository`, передавая им пути из `AppConfig`. Если в `Main` создаются `InMemoryUserRepository` и `InMemoryLinkRepository`, данные остаются только в оперативной памяти и исчезают после завершения процесса.

При использовании файловых реализаций данные размещаются в двух JSON-файлах:

```text
data/
├── users.json
└── links.json
```

`users.json` хранит UUID пользователей. `links.json` хранит короткий код, исходный URL, UUID владельца, время создания, точное время истечения, число использованных переходов и максимальный лимит.

Для TTL сохраняется абсолютный момент `expiresAt`, а не только длительность. Поэтому перезапуск приложения не должен начинать отсчёт срока заново.

Поведение файлового хранилища:

- если JSON-файла нет, репозиторий создаёт новый документ с пустым списком;
- если родительской директории нет, она создаётся;
- пустой или некорректный JSON считается ошибкой чтения, а не поводом молча перезаписать данные;
- запись выполняется через временный файл с последующей заменой основного файла; атомарность перемещения зависит от поддержки файловой системы.

Файлы `data/` не следует добавлять в Git: там находятся данные конкретного запуска приложения. Каталог `/data/` исключён в `.gitignore`.

## Уведомления и очистка TTL

Уведомления выводятся через `java.util.logging` в консольный журнал. Предусмотрены события:

- `LINK_EXPIRED` — ссылка удалена после истечения срока действия;
- `CLICK_LIMIT_REACHED` — достигнут лимит переходов;
- `SCHEDULER_ERROR` — планировщик не смог выполнить очистку.

Планировщик запускает очистку с интервалом, заданным в `link.cleanup.interval.seconds`. Он работает только пока приложение запущено. Консольный журнал не является постоянным архивом уведомлений.

## Архитектура проекта

```text
src/com/linkshortener/
├── app/                 # Точка входа и сборка зависимостей
├── browser/             # Реализация открытия URL в браузере
├── config/              # Чтение и проверка config.properties
├── model/               # User и LinkShort
├── notification/        # События и вывод уведомлений
├── repository/          # Интерфейсы хранилищ
│   ├── file/            # JSON-файловые реализации
│   └── memory/          # Реализации в памяти
├── scheduler/           # Планировщик очистки TTL
├── service/             # Бизнес-логика пользователей и ссылок
└── ui/                  # Консольное меню

test/
└── com/linkshortener/test/
    └── PersistenceSmokeTest.java
```

Основные обязанности слоёв:

- **app** — создаёт реализации репозиториев и сервисы, передаёт зависимости.
- **ui** — взаимодействует с пользователем и вызывает сервисы.
- **service** — реализует правила создания, посещения и управления ссылками.
- **repository** — предоставляет интерфейсы и отвечает за хранение данных.
- **model** — содержит состояние пользователя и короткой ссылки.
- **scheduler** — периодически запускает очистку просроченных записей.
- **notification** — формирует и выводит события приложения.

## Проверка сохранения данных

В проекте есть ручной smoke test `PersistenceSmokeTest`, который:

1. Создаёт временные JSON-файлы.
2. Сохраняет пользователя и короткую ссылку.
3. Учитывает несколько переходов и сохраняет обновлённое состояние.
4. Создаёт новые экземпляры файловых репозиториев.
5. Проверяет восстановление UUID, URL, счётчика, лимита, дат и поиска по владельцу.

Тест запускается вручную из IntelliJ IDEA через метод `main()` класса `com.linkshortener.test.PersistenceSmokeTest`.

Команда `mvn test-compile` компилирует тестовые исходники. Поскольку smoke test является обычным классом с `main()`, он не запускается автоматически командой `mvn test`. На текущем этапе полноценный набор JUnit-тестов не заявляется.

## Ограничения

- Приложение рассчитано на локальное консольное использование.
- UUID служит идентификатором пользователя, но не является полноценной аутентификацией: парольная защита не реализована.
- Браузер открывается на компьютере, где запущено приложение.
- Планировщик выполняет очистку только во время работы приложения.
- Уведомления выводятся в консольный журнал и не сохраняются как отдельная история.
- JSON-файлы предназначены для локального хранения небольшого объёма данных; это не замена многопользовательской серверной базе данных.
